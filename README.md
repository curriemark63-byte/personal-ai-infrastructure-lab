# My Personal AI Infrastructure Lab

## Overview

This repository documents my personal learning journey
in artificial intelligence, machine learning, Linux,
networking, and infrastructure engineering.

My goal is to develop a practical, locally operated
AI environment while building skills applicable to
data center operations, predictive maintenance,
and aerospace technology.

The lab is being developed in phases, progressing
from individual laptops and local AI models toward
a networked, miniature data center environment.

## Phase 1 – Foundations

### HP Laptop

My AI journey began with Python and machine
learning coursework.

Key activities:
- Python programming
- Machine learning fundamentals
- Jupyter notebooks
- Early AI experimentation
- Understanding model development

The HP laptop now serves as a Linux-based
infrastructure monitoring machine, with additional
monitoring capabilities planned.

## Phase 2 – Local AI Development

### Lenovo Legion

The Lenovo Legion was purchased to provide
additional computing resources for local AI
development and experimentation.

Hardware:
- AMD Ryzen 7 processor
- NVIDIA RTX 5060 GPU
- 48 GB RAM

Key activities:
- Local LLM deployment
- Docker containerization
- Retrieval-Augmented Generation (RAG)
- SearXNG self-hosted search
- AI coding assistant development
- Model testing and evaluation
- Agent security and watchdog development

This phase includes the development of
Ozzy and Tank.

## Phase 3 – Infrastructure Expansion

### Lenovo Yoga RTX Spark

The Lenovo Yoga was purchased to support larger
AI models and more advanced experimentation.

Hardware:
- NVIDIA RTX Spark GPU
- 64 GB LPDDR5X RAM
- 1 TB SSD
- Windows ARM64

Planned activities:
- Running larger language models
- Testing 7B and 30B coding models
- Comparing model performance
- Expanding AI development capabilities
- Evaluating models using identical test suites

### Network Attached Storage

UGREEN NASync 4800

Initial configuration:
- Four-bay NAS
- Two 8 TB Seagate IronWolf drives
- Ethernet connectivity
- Centralized model and file storage

Planned expansion:
- Additional RAM
- NVMe caching
- Higher-speed networking

### Networking

- 2.5 GbE network infrastructure
- Five-port Ethernet switch
- Eight-port switch ordered
- Shared storage access between machines
- UPS protection
- Dedicated Linux monitoring system

## Phase 4 – Kubernetes Infrastructure

The next major expansion involves building
a small Kubernetes cluster using refurbished
mini PCs.

Initial architecture:
- One control-plane node
- Two worker nodes

Planned experiments:
- Container orchestration
- Workload distribution
- Infrastructure monitoring
- Node failure simulation
- Service recovery
- System reliability testing
- Controlled failure and recovery experiments

The long-term objective is to create a
miniature data center environment for
hands-on infrastructure engineering.
